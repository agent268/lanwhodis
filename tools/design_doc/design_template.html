Design language · v2 · measured from two shipping apps

Calm navy surfaces, one blue accent, icons you can read at a glance.

Deckwork is the visual system shared by steamos-fm, a controller-first file manager, and LanWhodis, a network device scanner. It is written down here so a third project can pick it up. Every value on this page was read from the apps' own theme files, and the contrast numbers were measured, not assumed.

Qt Quick / QML3 themes: dark, light, Steam Deck Fluent UI icons, MITOne scale unit: 20 px × zoom

Foundations

Seven rules the rest follows from

These are the decisions that explain most of what you see. When a new screen has to choose, it chooses the way these do.

Layers are steps, not shadows

Each surface sits one clearly visible luminance step above the one beneath it, and edges are 1 px borders. There are no drop shadows. steamos-fm learned this on a handheld: when a button and its panel differed by a single step, the buttons were nearly invisible.

One accent, and it means "you can act on this"

Blue (orange in Steam Deck mode) marks selection, focus and primary actions. Green, amber and red report status. Category colors say what kind of thing a device is. The three never swap jobs.

Shape, color and word, together

A device is a glyph on a tinted tile plus a type label in words. Color alone never carries meaning, so the interface survives color blindness and a washed-out screen.

Pointer and controller first

Rows are 38 px tall at the base scale and text starts at 12 px. Touch works, but it does not set the size. The left stick on a Steam Deck is a precise pointer.

Show the reasoning

Detail panels list the evidence behind a verdict, with weights. Section titles are uppercase and letter-spaced, so a long panel stays scannable.

Every action has a key, and the footer says which

The hint bar is part of the layout. Plain-letter shortcuts are ignored while a text field has focus.

One unit scales everything

Sizes are multiples of a 20 px unit times the user's zoom. Change the unit and the whole interface rescales together.

Foundations

The same language in two apps

Deckwork started in steamos-fm and was refined in LanWhodis. The shared core is the palette, scale, shapes and component vocabulary. Each app adds a few tokens of its own: steamos-fm has file-kind tints and a pane header, LanWhodis has category colors and status tones.

Decisions that came from holding it in your hands

steamos-fm is tested on a handheld (ASUS ROG Ally X, 7 inch panel). Its source records what the device taught the design. These are why several tokens look the way they do.

Foundations

Type and scale

The app uses the platform's own interface font (Segoe UI on Windows, DejaVu Sans or the system font on Linux), so it feels native and needs no font files. What is fixed is the scale: five sizes, all multiples of the unit.

{{SCALE_ROWS}}
Token× unitpx at 1×Used forSample

Weights. Regular for running text and values. Bold for device names, type labels, primary buttons and chips. Nothing in between.

Section titles. Uppercase, bold, fontSizeSm, letter-spacing 0.08 × unit (1.6 px), dim color.

Monospace. IP addresses and MACs only. It makes columns of addresses line up and signals "this is a literal you may copy".

Measure. Detail values wrap at the panel width (about 56 characters at default zoom); long unbroken strings such as service URLs wrap anywhere instead of overflowing.

Foundations

Iconography

Microsoft's Fluent UI System Icons, filled variant, served as SVG and recolored at draw time so one file serves every theme. Each device type has one glyph and one category color; together they make a recognizable tile.

{{TYPE_GRID}}

Recipe. A rounded-square tile (radius 28% of its size) filled with the category color at 17% and outlined at 38%. The glyph fills 54% of the tile and uses the full category color.

Chrome icons (search, scan, edit, copy, filters) use the text color, or the accent when active or selected. They sit at about 1.1× the large text size.

Pinning. The bundled set is fetched by a script at a pinned commit, with the MIT notice stored beside it, so it is reproducible and can be refreshed deliberately.

States of the content area. Before the first scan: a centered tile, a headline, one sentence of reassurance and a single primary button. While the first results arrive: the same hero with a slowly pulsing halo and the live status line. When filters match nothing: a muted icon and a "Clear filters" button.

Feedback. Transient confirmations ("Copied 192.168.1.1", "Saved") appear as a small toast above the hint bar for 2.6 seconds. Long-lived state lives in the hint bar's status line.

Accessibility audit

Contrast was calculated for the pairs the interface really uses, in all three themes, against WCAG 2.x: 4.5:1 for normal text (including 15 px bold) and 3:1 for icons and large text. The first table is the shared core as LanWhodis ships it. The second is steamos-fm today, which has not adopted these fixes yet.

{{CONTRAST_SUMMARY}}

What the core changed, and why

Primary and danger buttons. White text on the bright accent blue was 2.75:1 (Deck orange 2.65:1). Black ink on the bright blue passed, but looked wrong next to light text everywhere else. The core now fills solid buttons with a deeper tone (accentFill, dangerFill) and uses white ink: {{FIX_RATIO}}:1 on dark, and the hover state stays above 4.5:1. The bright accent stays for icons, focus rings and links.

Dim text. steamos-fm's secondary text color is below 4.5:1 on its dialogs and section boxes. The core's textDim clears 4.5:1 on every panel surface in the dark and Deck themes.

Category colors. Yellow, teal, cyan and orange work as tile glyphs on a dark card but are too light as 15 px label text on white (Smart Home yellow was 1.9:1). The light theme uses darker label variants, drawn through Theme.labelColor; every category label now passes 4.5:1 in every theme.

Status chips. Light-theme chip text uses darker successText, warningText, dangerText tones; dark themes lighten the danger text.

Focus and motion. Keyboard focus is a 2 px accent ring just outside the control. Motion durations go to zero when the operating system asks to reduce motion. Components expose Accessible roles and names.

Tokens as code

The same tokens in two forms. The CSS block is ready for a web project; the QML file is the real theme singleton from the app.

CSS custom properties

{{CSS_VARS}}

Set data-theme="light" or data-theme="deck" on the root element, or leave it unset for dark. Units: --dw-unit: 20px; derive sizes with calc(var(--dw-unit) * 0.75) so a single zoom variable rescales the page.

Register it with singleton Theme 1.0 Theme.qml in a qmldir, then bind Theme.mode to your settings.

Lineage and credits

This language started in steamos-fm. LanWhodis kept its palette and component vocabulary and refined a few tokens on purpose. The core takes the refined values; steamos-fm has not adopted them yet.

{{LINEAGE}}
Tokensteamos-fm todayDeckwork coreWhy

Added to the core: inputSurface (a darker field for text inputs), success, warning, danger and their text tones, and the solid button tokens accentFill, dangerFill, accentInk, dangerInk.

Stays app-specific in steamos-fm: file-kind tints (archColor, exeColor, mediaColor), rowLine, focusRow, paneHeader and hidColor, which belong to a file browser.

Scale. steamos-fm sizes everything from the shorter screen dimension ÷ 40, because it runs full screen on a handheld. LanWhodis runs in a window, so its unit is a fixed 20 px times the user's zoom.
